# Andras Nemes: Week 1 pilot and harness write-up

Write-up for two Week 1 builds. Both include UI screenshots and several supporting documents, which puts them over this repo's contribution size limits for a direct PR, so this write-up stands in for them. The full files are in my fork, branch [`andras_nemes-week1-assignments`](https://github.com/andras-nemes/undercover/tree/andras_nemes-week1-assignments).

## Week 1 Day 3: the UnderCover pilot

Built the pilot end to end from `docs/SPEC.md`: backend, agent and dashboard. `npm run check` passes in full (ruff, pyright and pytest at 99% coverage; ESLint, Prettier, tsc and vitest at 100% statement coverage; 5 Playwright tests), with no test calling a model. A live run on the real model (`openai/gpt-6-luna`) over three claims showed the $1,000.00 sign-off limit enforced by the backend, not just the prompt: the agent tried to pay over the limit, the backend refused, and the claim waited for a handler's sign-off.

Takeaway: a plan with checkable criteria made "done" a fact rather than an opinion, and enforcing rules in the backend, not the prompt, is what held when the agent tried to pay over the limit anyway.

## Week 1 Day 5: the harness build

Extended the pilot with what `docs/HARNESS.md` asked for: a queue agent, a to-do list, a claim subagent, section-by-section document lookup, automatic recovery, DeepSeek V4.1 Flash as the default model, and two sets of instructions. A mid-build code review found the agent code short of pull-request quality (over twenty hardcoded backend URLs, two ways of calling the backend), and it was restructured before the build continued. A live run on the free model route hit the daily quota mid-run, and the recovery design handled it correctly: the run ended `failed` with a clear reason, and a retried claim was correctly left for a handler after its second failure.

Takeaway: a subagent per claim keeps the queue agent's context flat regardless of queue size, and the free route's outage during the live run proved the recovery design under a genuine failure, not a stub.
