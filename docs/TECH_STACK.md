# Tech stack

- `backend/`: FastAPI. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. Paying a claim is a separate operation that takes the amount, and a sign-off only records who signed off and when: the agent pays. The payout rules (`payouts.py`, from the policy wording and the plans) are an operation too, and the one place that knows the sign-off limit in `data/company.json`. The policy wording and the claims manual are split into their headed sections at load time, read by section rather than handed over whole. Claim status, steps and a run's to-do list (one row per claim it works, with its status and attempts) live in a database through SQLAlchemy Core, so each query is written once: Supabase Postgres when `DATABASE_URL` is in the environment (`npm run dev` passes `.env`; the tests never do), SQLite otherwise. On Postgres all our tables, the agent's saved progress included, are in the `undercover` schema, and a process uses at most 4 connections (the free plan allows 15 through the session pooler, across every process). `npm run seed` resets the database. Routes in `main.py` are thin; claim and run logic is in `claims.py` and `runs.py`, and `NotFound` and `Conflict` errors become 404 and 409 in one place. Money is `Decimal` dollars in Python, a two-decimal string on the wire and whole cents in the database (`backend/money.py`). A claim is decided once and paid once, enforced by a conditional `UPDATE`; repeating a decision or payment already recorded returns the claim, and a different decision on a decided claim is a 409. After a sign-off the backend tells the agent's service (`UNDERCOVER_AGENT`, or `http://127.0.0.1:8002`), once the sign-off is saved and without waiting for the payment.
- `agent/`: the claim agent is a hand-written LangGraph graph (`claim_graph.py`, `claim_nodes.py`, `claim_state.py`) whose progress is saved after every step in the same Supabase database by LangGraph's synchronous Postgres checkpointer (`checkpoint.py`, with `durability="sync"`). Its nodes call the model with the tools, read the decision back from the backend, wait for a sign-off with `interrupt()` when the backend says one is needed, and pay. The queue agent is a LangChain `create_agent`. Both reach claims, documents and instructions only through the backend's API; `api.py` is the only module that makes HTTP calls. `harness.py` builds the model and runs the queue agent (generic, no claims). `tools.py` holds every tool, each reading its state from `ToolRuntime[ClaimContext]` or `ToolRuntime[RunContext]`. `agents.py` has the entry points: `decide_claim(claim_id)` starts a claim or carries it on from its saved thread, `carry_on()` picks up the claims that were stopped or signed off while the agent was away, and `run_queue(cap=None)` finishes an unfinished run or starts one. `work.py` is the retry policy, deterministic Python rather than left to the model: a failed claim goes back in the queue on a new thread and is tried once more, then left for a handler; a stopped claim carries on without a new attempt. `__main__.py` starts runs (`uv run -m agent`), and `service.py` is the agent's web service, a fourth entry point, which `npm run dev` starts beside the backend and the dashboard on port 8002 and which carries a claim on after a sign-off. `tracing.py` sends each claim's work to Langfuse, in one session named after the claim and its thread. The model has a request timeout and a claim fails after 30 model calls. The default model is `deepseek/deepseek-v4.1-flash` at low reasoning effort, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`.
- `dashboard/`: React, Vite and TypeScript.
- `e2e/`: Playwright tests. They run the backend on SQLite and point it at a stand-in for the agent's service on port 8003.
- `data/`: the business data the backend starts from. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. The OpenRouter key is `OPENROUTER_API_KEY` in `.env`, with `DATABASE_URL` (the Supabase session pooler) and the Langfuse keys.
