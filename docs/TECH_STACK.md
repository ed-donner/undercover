# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core (`backend/store.py`), using Postgres (the `undercover` schema, with `pool_size=2, max_overflow=2`) when `DATABASE_URL` is set or SQLite in tests. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. It stores requests with their attempts, steps, recommendation and review (including `reviewed_by` and `reviewed_at`), and runs with their to-do lists and summaries, serves the policies section by section, and calculates policy-backed refunds in `backend/refunds.py`. `npm run seed` rebuilds the database. The product recommends support outcomes; it does not execute cancellations, returns, or refunds.
- `agent/`: OpenRouter, in two parts. The queue agent (`agent/queue.py`, `run_queue(run_id, cap)`) uses LangChain's `create_agent` to plan a run as a to-do list and hand each request to the request agent through its `work_request` tool, after first finishing any signed-off requests and resuming any mid-flight requests. The request agent (`agent/main.py`, `run_request(request_id, thread_id)`, wrapped by `work_request(request_id)`) is a hand-written synchronous LangGraph `StateGraph` (`agent`, `tools`, `decide`, `approval`, `complete`) compiled with `PostgresSaver` in the `undercover` schema (`durability="sync"`) when `DATABASE_URL` is set or `InMemorySaver` in tests. It works one request on a checkpointed thread per attempt (`{request_id}-attempt-{attempt}`), pauses at `approval` with `interrupt()`, and completes the request in `complete` when resumed after support sign-off. `agent/service.py` runs as a separate FastAPI web service on port `8002` (`UNDERCOVER_AGENT`), serving `GET /health`, `POST /requests/{request_id}/resume`, and `POST /runs`. When `LANGFUSE_SECRET_KEY` and `LANGFUSE_PUBLIC_KEY` are set, each request's work before and after sign-off is traced in one Langfuse session named after the request and its thread. LangChain middleware (`ModelRetryMiddleware` and `ToolRetryMiddleware`) and retry helpers handle passing errors, and an `after_agent` hook sends the queue agent back if it misses a waiting request within its cap. Both reach request, order, run, refund and policy data only through the backend's API. `uv run -m agent REQ-7001` works one request and `uv run -m agent --cap 5` starts a capped run. The default model is `deepseek/deepseek-v4.1-flash` with low reasoning effort, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`, with no reasoning effort set.
- `dashboard/`: React, Vite and TypeScript.
- `e2e/`: Playwright tests.
- `data/`: Shoppie's synthetic customer, order, and support request data. The agent never sees `data/evals/`, which holds reference decisions for evaluation.

Python 3.12 with uv, all in the root `pyproject.toml`. Node.js 24.15.0, pinned in `.nvmrc`. `.env` holds `OPENROUTER_API_KEY`, `DATABASE_URL` (for the local Docker Postgres container or Postgres instance), and optional `LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY`, and `LANGFUSE_BASE_URL`.
