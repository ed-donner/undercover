# Status

Building the pilot from `docs/PLAN.md`.

- `backend/`: `GET /api/health`. Reference data (plans, policies, customers, handlers, company settings, the policy wording) loads read-only from `data/*.json` into memory at import (`backend/data.py`). Claim status lives in SQLite (`backend/undercover.db`, gitignored), seeded from `data/claims.json` on first use (`backend/db.py`). Operations: `list_claims`, `get_claim`, `get_policy_wording`, `get_agent_instructions` (serves `backend/instructions.py`, read by both the agent and the dashboard), `decide_claim` (approve/decline/refer, moves an over-limit approval to `waiting for sign-off`), `record_step` (moves a claim from `waiting` to `in progress`), `list_claim_steps`, `sign_off_claim`, `pay_claim` (blocked until any required sign-off), `run_agent` (moves a `waiting` claim to `in progress` and schedules the agent's run on a `BackgroundTasks` task — its response is a bare DB row, not the full claim).
- `agent/`: `run(claim_id, thread_id)` fetches its instructions from the backend, then uses three tools — `get_claim`, `get_policy_wording`, `decide_claim` — each of which also records a step, so the backend's step log reflects exactly what the agent did. Checked against the real model on the 5 `tiny` sample claims: see `docs/PLAN.md` phase 3.
- `dashboard/`: React Router, with `/` the claims queue (a table with status badges), `/claims/:claimId` a claim's full page (story, items, policy, customer history, a "Run agent" button when waiting, a live step-by-step log while it works, and the decision once there is one — polls every 2 seconds while `in progress`), and `/instructions` the agent's instructions, read only. Brand fonts and colors from `docs/BRAND.md` apply globally, checked in light and dark mode. Checked end to end against a real claim: see `docs/PLAN.md` phase 5.
- `e2e/`: a smoke test that the queue page lists the claims.

Still to build: the sign-off/payment UI and the rest of the end-to-end Playwright tests.
