# Status

The pilot is built, from `docs/PLAN.md`. Run it with `npm run dev` (backend on :8000, dashboard on :5173) and check it with `npm run check`.

- `backend/`: `GET /api/health`. Reference data (plans, policies, customers, handlers, company settings, the policy wording) loads read-only from `data/*.json` into memory at import (`backend/data.py`). Claim status lives in SQLite (`backend/undercover.db`, gitignored), seeded from `data/claims.json` on first use (`backend/db.py`). Operations: `list_claims`, `get_claim`, `get_policy_wording`, `get_agent_instructions` (serves `backend/instructions.py`, read by both the agent and the dashboard), `list_handlers` (the handlers who can sign off an over-limit payout), `decide_claim` (approve/decline/refer; moves an over-limit approval to `waiting for sign-off`, else `decided`; clears any earlier sign-off and payment), `record_step` (moves a claim from `waiting` to `in progress`), `list_claim_steps`, `sign_off_claim`, `pay_claim` (blocked until any required sign-off), `run_agent` (moves a `waiting` claim to `in progress` and schedules the agent's run on a `BackgroundTasks` task — its response is a bare DB row, not the full claim).
- `agent/`: `run(claim_id, thread_id)` fetches its instructions from the backend, then uses three tools — `get_claim`, `get_policy_wording`, `decide_claim` — each of which also records a step, so the backend's step log reflects exactly what the agent did. Checked against the real model on the 5 `tiny` sample claims: see `docs/PLAN.md` phase 3.
- `dashboard/`: React Router, with `/` the claims queue (a table with status badges), `/claims/:claimId` a claim's full page (story, items, policy, customer history, a "Run agent" button when waiting, a live step-by-step log while it works, the decision once there is one, and — once it needs one — sign-off and "Release payment" controls), and `/instructions` the agent's instructions, read only. Brand fonts and colors from `docs/BRAND.md` apply globally, checked in light and dark mode.
- `e2e/`: the queue lists the claims and shows a claim's status badge through all four states; a decided claim's page shows its decision, payout and reason; the instructions page shows the agent's instructions; an over-limit approval blocks "Release payment" until a handler signs off. `e2e/globalSetup.ts` deletes the SQLite file before each run so every run starts from the same seeded queue.

`npm run check` passes in full: ruff, pyright, pytest (97% coverage), Prettier, ESLint, tsc, vitest (93% coverage), and the Playwright suite above.

Not built, per `docs/SPEC.md`'s "Not for now": the claims manual, sign-in, real payments, and messages to customers.
